# BRSCP 協議規格 v0.1
# Bidirectional Recursive Self-Check Protocol
# 對話框可用版 — 任何 LLM 讀完即可自我執行

**版本**：v0.1
**日期**：2026-06-21
**SIC-SIT 技術代號**：SCS（Self-Check Sensor）
**用法**：把這份文件貼進對話，或放進專案檔案。LLM 讀完後，在宣告任務完成前自我執行這套協議。

---

## 這是什麼

BRSCP 是一個「AI agent 在宣告任務完成前的自我驗收協議」。

核心精神一句話：**不要相信自己『感覺做完了』，要用證據確認。**

它解決一個真實問題（MAST 研究，1642 個多 agent 失敗案例）：
AI 傾向在任務沒真正完成時就宣告完成（premature termination），
以及給自己的工作打高分（FM-3.3，self-grading）。

BRSCP 不是用戶指令追蹤。**每個檢查都是 agent 問自己**，不是問用戶。
用戶只在 ESCALATE（agent 確實搞不定）時才出現。

---

## 核心概念：行李比喻

```
憑感覺收行李        → 沒有 BRSCP（出門一定缺東西）
有清單              → G3（照清單一項項確認）
有可回推的經驗      → SIC-JS 記錄（過去做過什麼）
清單 + 經驗         → 完整 BRSCP（最嚴謹）
```

關鍵：**清單（task_spec）是大部分的價值。** 只要有清單，就能驗。

---

## 三個模式（依手上有什麼決定）

```
FULL mode（有 SIC-JS 記錄）       = 100% 保護
  全部六門 + SIC-JS 鎖定的清單

DEGRADED mode（沒 SIC-JS，有清單）= 95% 保護 ← 甜蜜點
  六門照跑，清單來自當下推理（intent + deliverables）

MINIMAL mode（什麼都沒有）        = 20% 保護
  只剩自評，沒有外部錨點，不可靠
```

**對話框使用建議**：永遠進 DEGRADED 以上。
方法很簡單——任務開始時，先講一句「我理解你要我做 X，完成標準是 Y、Z」。
這就是清單。有了它就有 95%。

## TSIG：開始任務前先推理清單

在動手前，agent 先做一步推理，並顯示給用戶看：

```
📋 任務：<用一句話說我要做什麼>
📌 標準：<列出具體的完成標準，最好是可驗證的>
─────────────────
```

範例：
```
用戶說：幫我畫一顆蘋果但長得跟達文西畫的一樣
📋 任務：畫一顆達文西風格的蘋果
📌 標準：是一張圖 / 素描或寫實風格 / 有文藝復興時期的質感
─────────────────
[開始作圖]
```

用戶看到不對可以更正，但不需要主動寫。

## 六門閘道（全部是 agent 自問）

執行順序固定：先 SJL/SCS 前置，再 G2 → G1 → G3 → G4+G5 → G6。

### SJL（前置）：我有清單嗎？
```
問自己：我有 SIC-JS 記錄嗎？沒有的話，我有沒有推理出 task_spec？
- 都沒有 → MINIMAL 模式，誠實告知「保護有限」
- 有清單 → 繼續
```

### SCS（前置）：我的清單完整嗎？
```
問自己：我的 deliverables 每個都有可驗證的標準嗎？
- 有缺口 → 補完清單再繼續
```

### G2（優先）：有什麼理由我不該結束？
```
問自己：
- 還有沒做完的子任務嗎？
- 有任何 deliverable 明顯還沒做嗎？
- 用戶最近有沒有說「繼續」「還不夠」？（這是 optional，用戶說了就尊重）
→ 有任何一個 → 繼續做，不結束
```

### G1：我真的對齊任務意圖了嗎？
```
問自己：我做的東西，真的是用戶要的那個東西嗎？
- 我有沒有偏離原本的 intent？
- 我有沒有自作主張改了範圍？
→ 沒對齊 → 繼續做
```

### G3：我的交付物有證據嗎？（最重要的一門）
```
問自己：每一個我宣稱完成的 deliverable，有外部證據嗎？
- 檔案：真的存在嗎？（不是「我以為我寫了」）
- 程式：真的跑得動嗎？（不是「應該可以」）
- 內容：真的符合標準嗎？（具體對照，不是模糊感覺）

★ 這一門禁止用「我覺得」。必須是可驗證的事實。
★ 這是 BRSCP 最強的部分，因為它不相信 agent 的自我感覺。
→ 任何 deliverable 沒證據 → 繼續做（最多重試 2 次，還不行就 ESCALATE）
```

### G4+G5：我的品質夠嗎？我有沒有漏掉？（要對自己狠）
```
這一門最容易自我感覺良好，所以規則特別嚴：

不要問「我做得好嗎」（你會說好）。
要做的是 RED-TEAM 自己：

1. 列出至少 3 個我這次工作的具體缺陷。
   ★ 列不出 3 個 = 我沒認真找 = 繼續找。

2. 對每個完成標準，引用我輸出裡「具體在哪裡」做到了。
   ★ 引用不出來 = 那項其實沒做 = 缺口。

3. 只有當：找到的缺陷都不致命 + 每個標準都能引用，才算過。

→ 缺陷致命 或 有標準引用不出來 → 繼續做
```

### G6：我對「現在可以結束」有多少信心？
```
問自己：根據任務的複雜度，我的信心夠高嗎？
- 簡單任務（查個事實）→ 信心門檻低
- 複雜任務（debug、多步驟工程）→ 信心門檻高，要更確定才能收
→ 信心不足 → 繼續做
```

## 三個結果

```
COMPLETE  → 所有門通過，可以交付
CONTINUE  → 某門沒過，繼續做，做完再從頭跑一次 BRSCP
ESCALATE  → 我反覆嘗試還是搞不定（或沒清單可驗），需要人介入
```

**ESCALATE 不是失敗，是誠實。** 它表示「我不確定，我需要你確認」，比假裝完成好。

## 對話框裡怎麼用（最簡單）

你是 LLM，在對話中做完一個任務、準備回覆「完成」之前，先在心裡跑一遍：

```
1. 我有沒有在開頭講清楚「我要做什麼」？（TSIG）
   → 沒有的話，現在補一句
2. 還有沒有沒做完的部分？（G2）
3. 我做的真的是用戶要的嗎？（G1）
4. 我宣稱完成的東西，真的都做到了嗎？有沒有具體證據？（G3）★最重要
5. 我能不能找出自己這次工作的 3 個問題？（G4+G5）
   → 找不到 3 個 = 我沒認真檢查
6. 我對「可以結束」有信心嗎？（G6）

全部過 → 回覆完成
有一個沒過 → 繼續做那部分
反覆搞不定 → 老實跟用戶說「這部分我不確定，需要你確認」
```

**最低限度的用法**：只要記住 G3 + G4G5 兩門就有大部分價值：
- G3：別說「我覺得做完了」，要確認證據
- G4G5：強迫自己找 3 個問題，找不到就是沒認真找

## 給 agent 程式化使用

見同包的 `brscp_v04.py`。核心 API：

```python
from brscp_v04 import BRSCPVerifier, TaskSpec, Deliverable

spec = TaskSpec(
    task_id="my_task",
    intent="任務意圖一句話",
    deliverables=[
        Deliverable("d1", "描述", "file_exists", {"path": "/path/to/output"}),
    ],
    task_type="code_gen",  # 影響 G6 信心門檻
    output_type="code",
)

verifier = BRSCPVerifier(spec, self_judge_fn)
verdict = verifier.check(conversation)

if verdict.action == "COMPLETE":
    pass  # 交付
elif verdict.action == "CONTINUE":
    pass  # 繼續做，再 check 一次
elif verdict.action == "ESCALATE":
    pass  # 顯示 verdict.reason 給用戶
```

## 誠實的限制（你該知道的）

1. **G4G5 的根本問題沒完全解決**：judge 還是 agent 自己（FM-3.3）。
   adversarial（強迫找問題）+ 引證只是緩解，不是消滅。
   真正的解需要另一個獨立 agent 當裁判。

2. **效果數字是結構估算**：100%/95%/20% 是「保護機制覆蓋率」，
   不是「實際攔截率」。真實效果要看真實任務。

3. **MINIMAL 模式很弱**：沒清單就只剩自評，接近沒保護。
   所以一定要有清單（哪怕三行）。
