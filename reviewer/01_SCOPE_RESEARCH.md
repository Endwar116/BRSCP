# 包一：外部核對應該負責什麼

## 1. 問題與責任

任務來源是協德 2026-10-18 的 REQUEST-001 與補充 INFO-002，完整路徑見來源表。本輪交付支援設計與工程派工，沒有批准 BRSCP 新版本或正式部署。

外部核對負責檢查「目前固定的要求、證據、候選交付三者是否對得上」，並把核對範圍、缺證與技術失敗留成可讀取的結果。它不代替人類授權，不替來源證據保證世界真實性，也不替未執行的工具副作用補發批准。

本地現況：第二部分 3,600 列原始結果，重放包 1,860 筆已交答案、400 筆不全對；第九格 352 筆已交、62 筆不全對。這些是現有資料的重新計數。四家第九格不全對筆數依序是 deepseek 14/99、nemotron 27/98、gpt-oss 14/66、glm 7/89；分母都是已交答案，不能當作各家全部 100 次嘗試。

## 2. 三種方案與選擇

| 方案 | 優點 | 主要限制 | 採用位置 |
|---|---|---|---|
| 只用程式 | 快、可重跑、錯誤定位明確 | 有原文引用仍可能判斷錯誤 | 所有模式的第一層 |
| 一次無工具模型核對 | 易接既有呼叫器、可以讀內容 | 同源偏誤、提示注入、來源不足 | 本版主方案 |
| 可調工具的 reviewer agent | 可核對真檔與執行紀錄 | 權限、延遲與資料洩漏面擴大 | 另版，不混進本次實驗 |

主方案是第二項加第一項。輸入準備與證據擷取由受約束的控制程式負責；模型只收到完成判斷需要的材料。程式能確定的失敗先攔下；模型不重做檔案雜湊、版本與欄位檢查。

## 3. 對需求書七個問題逐題回答

### 3.1 核對者看什麼？

看匿名題目、依序列出的必要條款、對應原始證據片段、候選答案。疑點欄可以保留，但標為作答者主張，不給更高權威。外部模型的長篇自評、模型名稱、協議版本、實驗格、token 用量與標準答案不送入主方案。要求所有必要條款都有項目；空集合不得被當作全部通過。

作答者的完整推理不需要，也不要求私有思考過程。判斷理由以短句、條款編號和證據定位交付。程式修錯題另需受控測試結果，不能只有作者聲稱「測試通過」。

### 3.2 輸出什麼？

逐條回 `SUPPORTED / CONTRADICTED / INSUFFICIENT_EVIDENCE`，附證據編號與簡短理由，再由控制程式彙整。覆蓋清單必須與輸入要求完全相等，重複、漏項、加項都拒收。模型輸出自評信心不作主要門檻，先收集其校準資料再決定是否使用。

### 3.3 不同意之後怎麼辦？

有可定位矛盾：`RETURN_FOR_REVISION`；證據不足或技術失敗：`HOLD_FOR_EVIDENCE`。兩者都不讓高風險交付成功，但分開統計。控制程式不自動叫作者修、再叫 reviewer 重審，避免一次呼叫變成無限對話。作者修正後形成新 attempt，重新核對內容摘要；是否再花一次呼叫由新的工作預算管理。

低風險若明確設定只提示模式，可以交給人看原候選與 `UNREVIEWED` 標記。正式測試一律啟用阻擋模式，不能中途以提示模式補足通過率。

### 3.4 一個還是多個核對者？

預設一個，不用多人投票。不同模型家族只是降低一種相關風險，訓練資料、供應商與解題策略仍可能相關。實驗需要不同家族、相同模型再次判斷、隨機退回與純程式等對照，才知道價值來自內容核對還是多擋一些。

多核對者只作獨立研究分支，記總成本；不由 disagreement 自動再加第三位。涉及醫療、金流或不可逆操作仍有原業務審批，不能以模型多數決替代。

### 3.5 怎麼防止全部通過或全部退回？

以正確與錯誤的固定分母分別報抓錯率、誤擋率；加上全部放行、全部退回與同退回比例的隨機對照。故意放入「語氣很確定但錯」與「語氣不確定但對」的成對題。模型判定不送回後續題目的上下文，不讓它學到 labels。

### 3.6 成本設多少？

一次候選最多一次核對呼叫，輸入最多 6,000 tokens、輸出最多 800、合計最多 7,000，同時不得超過原作答總 token 的一半。全部含推理 token、快取命中 token 與傳輸重試的用量；缺 usage 記為成本未知而非零。無法精確預算的 adapter 不通過成本驗收。

牆鐘上限每筆 60 秒，排隊時間另列；不做自動重試。無法在預算放下全部必要證據時回 `INPUT_TOO_LARGE`，不得默默截斷。這些是工程設計值，不是假裝測得的最佳值。模型的長輸出並不必然更嚴謹；本版只要可定位的短理由。

### 3.7 怎麼接 BRSCP 與收尾閘？

提示協議增加可選的 external review policy，保留現行預設行為；控制程式必須真的呼叫 reviewer，貼一段條文不算接線。內部收尾閘 wrapper 在既有 `verifier.check` 後、正式輸出 COMPLETE 與 exit 0 前插入獨立裁定。現行路徑見規格。模型通過只解除內容核對這一項等待，不覆蓋來源、權限與人類批准的既有閘門。

## 4. 從扣評真實經驗形成的要求

| 經驗 | 可驗記錄 | 對本設計的改變 |
|---|---|---|
| 相似任務 gate 混淆 | `REVIEWER_ANCESTOR.md` 第五節與 2026-05-29 事件包；事件不能被擴寫成未證實的正式錯回 | 每次綁 request、target hash、attempt、allowed verdicts；舊結果不重用 |
| 空交付集合仍 COMPLETE | 2026-09-30 BRSCP wrapper 隔離報告 | 必要條款由上游固定來源提供；零項不能通過 |

| 零新材料的心跳選樣過窄 | 每日審查清單與 run log | reviewer 必記實際覆蓋集合；不能用「沒有矛盾」當「全部看過」 |

## 5. 校正文獻與原始需求中的強推論

Huang 等人的 ICLR 2024 研究在其設定下發現 intrinsic self-correction 困難，不能推出所有模型在所有提示下都無法自我修正。Liu 等人的 2024 工作報告在零溫度與公平提示下可觀察自我修正；目前查證到作者摘要與版本，並未重現其結果。自我核對應保留為實證對照。

MT-Bench 研究揭示位置、冗長、自我偏好與推理能力限制；其人類偏好一致率不能直接套用到 BRSCP 的事實完成判斷。OverclaimBench 檢查最終報告與逐字稿中的實際動作，適合支持「另查執行證據」，不支持「另一個模型一定能挑錯」。來源與核對程度見第四份文件。

兩個必要校正：

- 「只有外部模型才可能改善」過強；可執行測試、可信資料查詢、不同任務表示、改進基礎模型也可能改善。本次只隔離測第五部位的增量效果。
- 固定候選答案，只允許通過或退回時，令原先正確交付比例 T、錯誤交付比例 E、不交比例 A，抓錯率 c、誤擋率 f，則 T'=T(1-f)、E'=E(1-c)、A'=A+Ec+Tf。因此 A' 不小於 A。要同時降低錯交與不交，需另加修復、救回未交答案或換比較基線；這些不在本次單次 reviewer 主實驗。

## 6. 當前技術評級

使用本包自訂四層：設計、隔離合約可跑、模型效益實測、正式 consumer 驗收。現在到第二層的局部合約；模型效益與正式接線仍待驗。這不是公開排名、產品安全等級或對 SIC-SIT 全宇宙的總裁定。
